Take-home summary

Agentic AI, without the hype

Everything from the masterclass, distilled. The headline of the whole class: the model is already smart enough — what's missing is context. Get the context right and one prompt comes back 90–95% ready. Pages 2–3 are the heart of it: CLAUDE.md (how AI boots into your world) and hooks & gates (how it stays reliable and gets better every run).

iThe one idea everything hangs on

"AI is like the partner in 50 First Dates — brilliant, but forgets you every morning. Your job is to give it a memory."

AI has no memory by default. Without context it guesses, sounds confident, and hands you generic work — garbage in, garbage out. The skill that changes your output isn't a cleverer prompt — it's context engineering: onboarding AI like a new hire who already knows your business, your rules, your taste, and your past decisions before it says a word.

1The three A's — Automation · Augmentation · Agency

Three different ways to work with AI. Most disappointment comes from using the wrong one for the task. Decide the mode first — the tool follows.

Mode A

Automation

A fixed flow that runs the exact same steps every time. Rule-based and deterministic — zero deviation. Don't use a reasoning model here; it drifts ~10% of the time.

WHEN: it must be 100% consistent.
e.g. scan invoices → Airtable, every time.
TOOLS: n8n · Zapier
Mode B · most of your day

Augmentation

Human does the work with AI. You prompt, it drafts / researches / reasons, you stay in the loop and edit. "50% me, 50% Claude" — where most real output happens.

WHEN: judgment + speed together.
e.g. drafting, analysis, research.
TOOLS: Claude Cowork · ChatGPT
Mode C

Agency · agents

AI works toward a goal without step-by-step direction — the "runs while you sleep" promise. Real today, but needs setup; start with a recurring task you already have.

WHEN: a recurring 80% can run itself.
e.g. a daily report that just appears.
TOOLS: Claude Code agents · cron
2The three Claude "rooms" — and why they don't talk

Same brain, three setups. The trap is switching between them mid-task — they don't share memory. Pick one main room and stay there.

RoomWhat it isCan doWatch out
ChatA smart colleague you talk toThinking, drafting, research — fast, cheap on tokensNo access to your files or stack; won't do the work for you
CoworkA personal assistant in a sandboxReal tasks via authorised connectors; remembers connectionsLimited to Anthropic-approved connectors
Claude CodeFully personalised to youFull computer access; build custom skills, agents, hooksMost power, most setup; no vision — can't see screens

The reasoning model is an orchestrator: it plans, then calls specialists it can't do itself — Nano Banana / GPT Image for images, Sora / Veo 3 / Seedance for video — and reaches your stack (Ahrefs, HubSpot, GSC…) through connectors / MCP.

3CLAUDE.md — the briefing AI reads before it says a word

This is the single highest-leverage file you'll build. Skills, agents and hooks load on demand — CLAUDE.md loads every single turn. It's the one place guaranteed to be read. Put your business context here and the model boots into your world: new session → blank brain → reads CLAUDE.md automatically → shows up knowing your voice, rules and playbooks before turn one.

Layer it like an onion.  Claude reads the nearest file, then walks up the chain.
Broad at the top, specific at the bottom — and more-specific wins. Nested context that loads only when relevant beats one giant file.
~/.claude/CLAUDE.md ← you · every project (who you are, how you write) └─ ~/business/CLAUDE.md ← the business · voice + brand rules ├─ company/CLAUDE.md ← content register ├─ clients/acme/CLAUDE.md ← client facts · analytics IDs · competitors │ └─ content/CLAUDE.md ← workstream specifics └─ prospects/…/CLAUDE.md ← one file per prospect
~/.claude/CLAUDE.md  · global · every project
  • Who you are · how you communicate
  • Universal rules & file/tool conventions
  • "Be brutally honest. Plain language. Never dump files in the wrong place."
./CLAUDE.md  · project · this client only
  • Overview · brand voice
  • Data sources & IDs (e.g. GA4 property)
  • Known quirks & gotchas for this account
✓ Keep it tight. Loads every turn — aim < 300 lines. Scrolling = too long. ✕ Repeatable steps? That's a skill (loads on demand), not CLAUDE.md. ✕ A reusable fact? Put it in MEMORY.md, not a wall of text.

Not just Claude — every tool reads a context file: AGENTS.md (Codex, and the shared standard most tools read) · GEMINI.md · .cursor/rules · copilot-instructions.md. Mixed-tool team? Put shared context in AGENTS.md; keep tool-specific rules in that tool's own file.

4Two reusable workers: Skills & Agents
A saved recipe · /command

Skill

A step-by-step procedure you froze after it worked, invoked with a slash command. Tina's bookkeeping skill replays steps 1–20 exactly as she did them the first time. Rule: anything you've done the same way twice should be a /command, not a conversation. She has 100+.

An employee · its own context

Agent

A role with a persistent profile — your tone, your past emails, one specialty. You don't re-brief it. Tina runs 16: chief-of-staff, technical-SEO, writer, linkedin-writer. A focused agent beats a generalist — same reason you hire a copywriter, not ask your accountant to write copy.

5Hooks & Gates — make "good" a file + a check, not a hope

This is what turns a clever demo into something you can trust unattended. Don't hope for quality — put a deterministic check in the path. Three pieces work together as the harness:

Agent
one job per worker

Each agent gets a fresh start and one clear task. The collect-agent never sees the report-agent's mess. Hire a specialist per job, not one generalist doing everything.

Hook
runs without you watching

An automatic tripwire your computer runs — not Claude. Fires on events: before risky moves (block writes to secrets), after every edit (catch breakage), when Claude stops (capture the lesson). You don't have to be in the room.

Gate
it can't talk its way past

A real code check, not a prompt. "Report says 27,659 keywords. Raw file says 15,164. Don't match → fail → retry." The model cannot argue with an exit code.

Live example · the slop check

A hook that guards your voice

Edit any content file → a PostToolUse hook fires automatically → runs slop-check.py → injects the score + flagged phrases back into context. "I never have to remember to run it. I never have to ask Claude nicely."

// ~/.claude/settings.json "PostToolUse": [{ "matcher": "Edit|Write", "command": "python3 slop-check.py" }] FAIL — 3 violations: [isnt-its] "isn't X. It's Y" [todays] "In today's fast-paced…" [banned] game-changer
Principle 1 · corrections compound

The learnings loop

When Claude stops, a hook writes one line to CLAUDE.md / MEMORY.md — and the next session reads it back. The agent walks in already knowing the lesson.

It isn't fine-tuning — no weights, no GPU, no data team. It just changes what the model knows before it starts. A text file does the job.

The payoff: most agents stay flat — run 10 looks like run 1. This one is measurably sharper at run 10. Every correction logged = one less repeated mistake, forever.

6Tina's 6 principles, in one breath
1
Corrections are permanent, not per-session.
Catch a mistake → write it to CLAUDE.md → it never repeats. A toy vs a tool is whether corrections compound.
2
Encode your taste as code, not vibes.
Don't hope for on-brand output — a hook enforces it. When quality matters, put a deterministic gate in the path.
3
Layer your context like an onion.
Global → project → live state. One giant file doesn't scale; nested context that loads when relevant does.
4
Promote a procedure to a skill the moment you repeat it twice.
Done it twice the same way? It's a /command, not a conversation.
5
Delegate to specialists, not one generalist.
A focused agent beats a general one — hire a copywriter, not your accountant.
6
Make Claude work when you're not there.
The frontier isn't "answers faster." It's "runs the recurring 80% on its own, pings you on novelty."
